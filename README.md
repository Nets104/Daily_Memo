# 일상 기록 — 모바일 기록 웹앱

글, 사진, GIF, 음성 및 PDF를 남기는 PWA입니다. 로그인한 기록은 Supabase 비공개 서버에, 비회원 기록은 해당 기기의 IndexedDB에 저장합니다.

## 기능
- 월별 달력에서 기록이 있는 날짜 확인 및 날짜를 눌러 기록 열기 (기록이 없는 날은 새 기록 생성)
- 날짜 자동 입력 + 일본어 요일 표기 `2026-10-31(土)`; 제목·본문 작성
- Markdown 작성 도구 (제목, 굵게, 기울임, 밑줄 `<u>`, 취소선, 목록, 체크박스, 인용, 코드, 구분선, 링크)
- 작성 / 미리보기 / 나란히 편집; 자동 저장; 날짜·제목·본문 검색
- 사진·GIF·음성·PDF 첨부; 마이크 직접 녹음(권한 필요)
- 현재 기록 Markdown / PNG / A4 PDF / 원본 파일 포함 ZIP으로 내보내기
- 전체 기록과 첨부 파일 ZIP 백업 및 복원
- Pretendard 웹 폰트 (네트워크 불가 시 시스템 폰트 대체)
- 홈 화면에 추가 가능; 설치 후 핵심 기능 오프라인 사용

## 설치 및 사용
1. 이 폴더의 **파일 전부**를 GitHub Pages 또는 Netlify 등 HTTPS 정적 호스팅에 업로드합니다. (서버/DB 필요 없음)
2. Android Chrome에서 배포 주소를 열고 메뉴(⋮) → **홈 화면에 추가 / 앱 설치**를 선택합니다.
3. 데이터는 해당 비회원 모드에서는 **사이트 주소의 브라우저 IndexedDB**에 저장됩니다. 같은 사이트라도 다른 브라우저/다른 휴대폰에서는 자동 동기화되지 않습니다.
4. 왼쪽 목록의 **전체 백업 ZIP**을 주기적으로 내보내 두세요. 브라우저 데이터 삭제나 사이트 주소 변경 전에 백업해야 합니다.

`index.html`을 직접 열어 볼 수도 있지만, 홈 화면 앱 설치 및 마이크 녹음 등 일부 기능은 HTTPS 배포가 필요합니다.

## 주의사항
- 백업은 **무압축 ZIP**으로 생성됩니다. 앱 내 백업 불러오기는 앱이 만든 무압축 ZIP 형식만 지원합니다.
- PDF는 본문을 이미지로 그려 생성하므로 검색/텍스트 선택이 되지 않습니다. 텍스트 원본은 `.md`를 사용하세요.
- 긴 글의 PNG 내보내기는 하나의 세로 이미지로 생성됩니다. 7페이지 이상이면 PNG 여러 장을 ZIP으로 내려받습니다.
- 동영상과 음성은 PDF/PNG에서 이름으로 표시되며, 원본은 해당 기록 ZIP에 포함됩니다.
- 브라우저 저장 가능 공간은 기기마다 다릅니다. 앱의 첨부파일 정책은 아래의 백업 및 첨부파일 정책을 참고하세요.
- 로그인 모드에서는 계정별로 서버에 저장합니다. 비회원 기록은 서버로 전송하지 않습니다. 외부 글꼴 CSS는 처음 로딩 때 CDN에 요청될 수 있습니다.

## GitHub Pages 배포 예시
1. GitHub에서 공개 또는 비공개 저장소를 새로 만듭니다. (선택한 플랜의 GitHub Pages 지원 여부 확인)
2. 압축 파일을 풀고 `index.html`, `style.css`, `app.js`, `sw.js`, `manifest.webmanifest`, `icons/` 폴더를 **저장소의 최상위**에 업로드합니다.
3. 저장소 **Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save**를 선택합니다.
4. GitHub Pages가 안내하는 HTTPS 주소에서 사이트를 연 뒤, 휴대폰 Chrome의 메뉴에서 **홈 화면에 추가 / 앱 설치**를 선택합니다.

배포 시 **비공개 일기가 GitHub에 업로드되는 것은 아닙니다.** GitHub에는 앱 코드만 올라가며, 일기와 첨부 파일은 사용 중인 브라우저의 로컬 저장소에 보관됩니다. 단, 기기 분실이나 타인과의 기기 공유를 고려해 잠금 화면과 파일 백업 관리에 주의하세요.

## 서버 저장 (Supabase)
1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql`을 실행합니다.
2. Authentication → Providers → Email을 설정합니다. 이메일 확인과 사이트 리디렉션 URL을 확인하세요.
3. Project URL과 Publishable key를 `supabase-config.js`에 설정합니다. **service_role / secret key는 절대 사용하지 마세요.**
4. 정적 페이지를 갱신하면 이메일 가입/로그인이 나타납니다. 각 계정은 RLS로 분리됩니다.
5. 로그인 후 ‘이 기기의 기존 기록 가져오기’를 누르면 로컬 데이터가 서버로 복사됩니다. 기존 로컬 데이터는 삭제되지 않습니다.
6. 서버 설정 전에는 로컬 모드로 작동합니다. 서버 저장을 사용할 때는 `storage-quota.sql`과 `save-diary-attachment` 함수도 함께 설치하세요.

※ Cloud 모드에서는 로그인 상태에만 기록을 조회합니다. 오프라인 편집은 지원하지 않으며 동기화 실패 시 재시도해야 합니다. 익명 공개 사용자가 인증 데이터를 읽을 수 없도록 정책을 유지하세요.

## 백업 및 첨부파일 정책 (2026-11-02)

- 메뉴의 백업·복원·삭제 버튼은 계정 영역 위에 있습니다.
- 백업/삭제 범위: 이번 달, 전체, 시작일~종료일(양 끝 날짜 포함).
- 백업 ZIP 준비 후 내 기기에 저장하거나 Web Share로 외부 공유합니다. ZIP 공유를 지원하지 않는 브라우저에서는 파일을 저장한 뒤 원하는 앱에서 첨부합니다. Google Drive 직접 연동은 아닙니다.
- 일반 사진은 장당 1MB 이하로 자동 압축합니다. GIF는 애니메이션 원본을 유지하며 2MB까지 허용합니다. 일기 하나에 사진/GIF 최대 10장, 여러 장 동시 선택 및 후속 추가 선택을 지원합니다.
- 같은 날짜의 모든 기록/썸네일/첨부 합계 10MB, 개인 첨부 합계 250MB. MB는 1,000,000바이트 기준입니다. 새 영상 업로드는 지원하지 않습니다. 기존 영상 조회/백업은 유지되며 영상 포함 백업의 복원은 쓰기 전에 중단합니다.
- 개인 사용량 200MB(80%)부터 지난달 백업을 안내합니다. 백업 자체로 서버 파일은 삭제되지 않습니다.
- 서버 강제 검사 준비 파일: `supabase/storage-quota.sql`, `supabase/functions/save-diary-attachment/index.ts`.
- 서버 용량 정책과 업로드 함수가 적용되어 브라우저 밖의 요청에도 같은 제한이 적용됩니다.
- 새 Supabase 프로젝트에 설치할 때는 quota SQL과 Edge Function을 함께 배포하세요. Edge Function은 매 요청마다 Auth `getUser()`로 인증하고 service-role 키는 함수 환경변수에서만 사용합니다. Storage 직접 쓰기는 quota SQL의 제한 정책으로 차단됩니다.
- 서버 활성화 시 모든 프로젝트 버킷의 실시간 파일 합계가 800MB 이상이면 지난달 백업 안내를 표시합니다. 이는 Supabase의 월평균 청구 사용량/DB 용량 지표와 별개입니다.

### 검증 기록

- PC 1920/1366px 및 모바일 390/360px에서 캘린더 아이콘/한마디, 백업 창, 메뉴 타일을 점검했습니다. 마이페이지는 PC/모바일에서 버튼 높이와 글자 크기를 확인했습니다.
- 격리된 브라우저 저장소에서 날짜 경계를 포함한 ZIP 백업/복원, 범위 삭제/전체 삭제 확인, 사진 다중·후속 선택, 압축, GIF 바이트 보존, 영상 차단, 좌우 이동과 미저장 확인을 검증했습니다. 외부 앱에 실제 파일을 보내지는 않았으며 공유 API 분기는 모의 검증했습니다.
- 실제 서버에서 업로드 예약, 다른 일기와 합산한 일일 한도, 날짜 이동 검사, 개인 한도, RPC 권한을 검증한 뒤 테스트 트랜잭션 전체를 롤백했습니다. 테스트 기록·예약이 남지 않았음을 확인했습니다.
- 보안 검사에서 새 private 테이블은 기본 거부(RLS 활성화·직접 권한 없음)입니다. 기존 인증 관련 경고는 이번 작업에서 변경하지 않았습니다: [사용자명 조회 함수 권한 안내](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [유출 비밀번호 보호 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
